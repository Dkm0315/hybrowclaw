# Muster Frappe AI OS Acceptance Matrix

| Gate | Required proof |
|---|---|
| Universal Ask | same prompt surface answers general guidance and selected-record questions; performs RBAC-filtered detail/list/count/aggregate reads; creates verified artifacts; proposes one-off actions and reusable workflows without silently executing; routes development/customization requests to privileged review; current page is context rather than a scope ceiling |
| Install and migration | clean Frappe-only v16 install, repeated migrate, upgrade, backup/restore, safe uninstall, optional ERPNext/custom-app discovery, no customer-bench changes |
| Roles and tenants | every role by DocType/API/action; own/other/company/site; list/report/export/share/realtime/download; expired/revoked permission; deny with zero side effects |
| Business CRUD | create/read/update/delete, submit/cancel and native Workflow actions on standard and custom DocTypes under the real caller, including permlevel/masked fields |
| Attended CRUD truth | create/read/update is performed on the actual Desk form with the visible `Muster has taken over` cursor; effective Custom Fields, Property Setters, workflow state and field permissions are identified before action; schema drift, injected Client Script/DOM instructions, false cursor events and hidden-REST substitution fail closed; server reread proves the result |
| Native app surfaces | the same natural-language entry and visible-control contract is proven independently in ERPNext/HRMS Desk, CRM, Helpdesk and at least one custom Vue/React Frappe app; each adapter declares supported routes/actions/version, fails closed when incompatible, and never substitutes Desk or hidden REST for claimed native UI work |
| Partial intent | incomplete create requests use authoritative defaults and ask only for required values with no safe default; incomplete update/delete requests resolve exactly one permitted record or present bounded disambiguation; no record identity or business value is guessed; concurrent revision drift returns for review |
| Customization | propose, preflight, approve, apply, verify and reverse/repair every supported metadata/UI/report/print/web/integration surface; validate actual rendered behavior |
| Effective customization truth | runnable cases cover Custom Fields, Property Setters, permlevels, naming, child tables, Client Scripts as untrusted runtime behavior, Server Scripts where enabled, native Workflows, submitted-document rules, reports, Print Formats, Email Templates, Web Forms, Workspaces and custom pages; Frappe v16's Quick Entry skeleton write for new DocTypes is shown and receipt-bound as a compensating two-stage saga; both standard and customized forms are visually verified |
| SOP/PRD/design ingestion | authenticated files from Frappe File or the chat attachment surface are content-scanned, size/type bounded, authority-bound and converted into cited requirements; ambiguous/conflicting requirements pause for clarification; the reviewed implementation graph traces every change and verification back to source passages without treating document instructions as authority |
| Frappe coding ladder | runnable evidence progresses from no-code metadata through existing-DocType controllers and `doc_events`, ordinary form/list JavaScript, fixtures, whitelisted APIs, permission-filtered ORM/Query Builder, Query/Script Reports, Jinja Print/Email/Web rendering, scheduler/background work, optional pages or Vue/React SPAs, patches/migrations, tests, build/deploy and rollback; beginner prompts receive guided explanations while advanced prompts use a registered app, isolated worktree, reviewed diff and negative/upgrade verification |
| Orchestration | three nesting levels, fan-out/join, bounded loop, retries, timeout, pause/steer/resume/cancel, budget/concurrency caps, duplicate request, worker death and dependency outage recovery |
| Desktop/mobile UI | 1440/1024/430/390/320 widths, supported browsers, keyboard/touch/screen reader/reduced motion, background navigation, multi-mission, multi-tab and reconnect without duplicate events |
| Security | threat-model negative suite: CSRF/POST, OAuth/Telegram/webhook replay, SSRF/injection/XSS/path traversal, secret redaction, approval/lease fencing, no permission laundering |
| Scale | deterministic 30 users, six roles, four companies, 20 agents, 12 workflows, 10k missions and 100k activities; indexed pagination, queue fairness and declared p95/p99 thresholds |
| Operations | health, queues, scheduler, socket, gateway, metrics/traces/logs, retention, backup/restore, cutover and rollback rehearsal |
| Evidence | immutable revisions/environment, seed ids, expected/actual and side-effect assertions, artifact hashes, screenshots/traces, and claim-to-video timestamps in a passing JSON manifest |

Blocking thresholds: zero tenant/RBAC leaks; zero lost or duplicated committed effects; zero unresolved critical/high security findings; all migration and restore cases pass; no skipped or flaky blocking case. Performance thresholds are set before the measured run and stored in the manifest.
